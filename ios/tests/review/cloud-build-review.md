# Independent CloudBuild template review

2026-10-16. Read-only review of `CloudBuild/codemagic.yaml`, `scripts/fetch_source.py`, `scripts/test_fetch_source.py`, and README. No implementation or README was changed. Only constructed ZIP fixtures were executed; no source URL, cloud account, upload, Apple build, live game account or TCP connection was used.

**Result: no blocking defect found in the reviewed template. All nine offline fixtures passed. The cloud workflow itself has not run and no real IPA is claimed.**

The documented placement is correct: copy CloudBuild's contents to the small repository root. The first step calls `scripts/fetch_source.py --destination .work/source`; verified extraction publishes `ios/` beneath that directory. Both following commands therefore resolve `.work/source/ios/tools/...`. The unsigned shell's default output is under that same `ios/build`, matching the configured IPA/audit artifact globs. Each command uses failure/pipe handling so a failed native test or archive does not produce a reported successful build step.

The private URL remains an environment value used directly by urllib; it is not interpolated into a shell or printed. URL validation requires HTTPS without userinfo/fragment, including redirect targets. Raw download/network exceptions are replaced with fixed messages. The source ZIP SHA256 is checked before extraction or executing any fetched build code. ZIP members require a canonical relative `ios/` path, disallow symlinks and duplicates/case collisions, and enforce file/byte limits. Extraction uses a newly created staging directory, checks the exact internal manifest file set and every declared size/hash, requires the complete unsigned build path, then publishes the verified directory. Existing destinations are preserved.

Manifest failure paths do not print entry contents, private configuration, URL tokens or raw library exceptions. The later build/verification scripts were also checked for their log contract: they report paths, hashes, compiler output and boolean configuration presence, rather than printing the source URL or NativeConfig content. The template provides no signing secret, publishing, notification, automatic trigger or live game login. Source storage and source-bundle confidentiality remain the user's explicit private setup, as documented.

Executed: `python ios/CloudBuild/scripts/test_fetch_source.py` — **9 tests, 0 failures/errors**. Coverage includes successful verified extraction without executing fixture scripts, outer SHA failure, content/file-list manifest mismatch, path traversal/noncanonical names, symlinks and case collisions, existing destination preservation, HTTPS/redirect validation, URL-token error redaction and archive limits. These tests use tiny synthetic ZIPs; they do not download or unpack the full source bundle.
